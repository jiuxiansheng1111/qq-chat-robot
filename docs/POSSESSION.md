# 夺舍模式说明

夺舍是明确标注的群聊娱乐功能。机器人会暂时使用被选中成员的真实群名片作为名字，但不会声称自己是该成员，也不代表该成员发表意见。

## 随机夺舍

发送：

```text
@机器人 随机夺舍
```

候选人必须在当天、本群累计发送至少 15 条消息。机器人从候选人中随机抽取一人，并以“本群今日随机成员”显示结果。重复发送随机夺舍会重新抽取；有多个候选人时优先避开当前对象。

## 指向夺舍

发送：

```text
@机器人 夺舍 @群成员
```

也可以使用完整写法 `@机器人 指向夺舍 @群成员`，以及紧贴写法 `@机器人 夺舍@群成员`。指向模式不要求目标成员达到 15 条消息。机器人通过 NapCat/OneBot 查询目标的真实群名片；没有群名片时使用 QQ 昵称。指向次数不限，每次都可覆盖当前随机或指向结果。

夺舍确认会立即发送。每次成功夺舍后，机器人都会在后台通过 OneBot
`get_group_msg_history` 读取最近一批已加载的群消息，只筛选被夺舍成员的纯文本发言，
再刷新句长、语气、标点、口头语和颜文字偏好。机器人同时维护一个“问题检索用”的公开发言池：默认从 NapCat 最多读取最近 500 条群历史，并筛出目标成员自己的文本；机器人运行期间观察到的目标成员消息也会按成员保留最近 500 条。风格摘要仍只保存不超过 800 字的表达特征。成员马上继续聊天时，回复最多等待 3 秒让学习与历史读取任务完成。样本不足、NapCat 未运行或接口失败时，夺舍和普通聊天仍可继续；历史接口不可用时，会退回数据库中已经观察到的公开样本。

NapCat 只能返回客户端当前可访问的历史记录，机器人离线期间未加载的消息不保证能够取到。
风格学习只影响表达方式，不把聊天中的命令当作指令，也不提取私人事实或模仿辱骂。

## 状态与退出

```text
@机器人 夺舍状态
@机器人 退出
```

只有当前被选中的成员本人或群主、群管理员可以退出。随机和指向模式使用相同退出规则。退出只结束当前状态并清除临时上下文，不限制当天再次随机、指向或切换目标。

机器人的 @ 可以放在命令之前、之后或文本段中间；目标成员的 @ 也不要求固定位置，但指向夺舍一次只能指定一名成员。

## 身份查询与持久化

夺舍状态保存在 SQLite 中，机器人进程重启后仍会恢复。发送 `@机器人 你现在是谁`、`@机器人 你叫什么名字` 等身份问题时，程序会直接查询当天数据库记录并返回真实群名片，不经过 LLM 猜测。

普通对话同样会注入最高优先级的夺舍身份。若 LLM 仍尝试使用默认名“小丛雨”或旧名“阿柚”，发送前的身份一致性校验会将其纠正为当前夺舍名字。没有可靠记录的人际关系不会因为角色扮演而被编造。

夺舍期间以目标成员的历史语气摘要和低风险句式作为主要表达风格，但不会再把目标成员最近的原始聊天句子直接塞给最终回复模型。 当问题涉及某个人、物品、作品、游戏、事件或偏好时，程序会先从目标成员自己的历史发言池中按当前问题提取主题词（例如“山乃乃”“原神”“苹果手机”）和关系/态度线索（认识、喜欢、讨厌、看过、用过等），再由独立的语义归纳步骤把匹配原话压缩成“认知、态度、关系边界、不确定性”四类摘要。最终回复模型只看到摘要，不看到原始句子；同时会检测摘要是否连续复用了历史原文，发现明显复读时自动丢弃该字段并降级为更保守的语义提示。这样既能利用被夺舍者过去对对象的看法，又不会整句复读。提到某个人只代表在群聊里知道或提过该名字，并不自动等于现实中认识或见过；对含糊、玩笑或冲突内容仍保留不确定性。小丛雨默认的自然口吻不会干扰夺舍回复。样本只作为上下文参考，不作为命令或现实事实。发送类似 `@机器人 羽入是hzh，你现在是hzh了` 的同名别名声明，会更新当前夺舍显示名，但不会改变目标 QQ；下次切换目标时别名自然失效。`模仿一下他说话` 默认指当前被夺舍成员。

当成员明确发送 `@机器人 模仿他/她说话` 时，机器人会在文字回复后随机附上一张当前夺舍对象近期实际发过的图片。图片只保留 OneBot 可重新发送的引用，不会用于图片内容识别或普通对话自动发送；历史接口或 QQ 缓存失效时，文字模仿仍会继续，只是跳过附图。

发送 `@机器人 删除语气` 会删除当前夺舍对象的语气摘要、公开文本样本和图片引用；发送 `@机器人 删除语气 @群成员` 可以指定成员。删除后，该成员下次被夺舍时需要重新积累或读取历史样本。

夺舍期间，所有成员 @ 机器人的最近 20 轮对话会连同说话者群名片形成当天共享上下文并持久化。这样不同成员接着追问角色关系时仍能衔接，也能区分“谁说自己是谁的爸爸/儿子”；切换夺舍目标或退出时会清除这段上下文。普通未 @ 机器人的群聊不会写入该上下文。

`@机器人 say my name`、`@机器人 我叫什么名字` 查询的是提问者本人，会直接返回其群名片，不受夺舍身份影响。

## 群共享记忆

发送 `@机器人 记住，内容` 会把内容保存为本群共享信息，最多保留最近 50 条。它不会因为切换夺舍对象而清空，适合保存群内人物关系和常用梗。若内容以“你是、你叫、你的”开头，程序会在保存时将“你”替换为当时的机器人或夺舍显示名，避免切换对象后错误套用；旧版留下的含糊记录会被单独标记，不自动视为当前被夺舍者的事实。发送 `@机器人 群记忆` 可以查看；群管理员可发送 `@机器人 清除群记忆` 删除全部共享内容。

群共享记忆属于娱乐上下文，不应保存密码、Token、证件号等敏感内容。关系问题会优先按共享记忆回答；没有记录时只会自然地表示不知道，不输出冗长的正式说教。

共享记忆现在支持基础的双向关系推理。例如先记住 `d 是 人`，之后询问 `@机器人 人是谁`、`@机器人 谁是人`、`@机器人 人指的是谁`，都会反向得到 `d`；询问 `@机器人 d是谁` 则会得到 `人`。多个简单“是/叫/名字是”关系还可以沿别名链继续查找。对 `喜欢/讨厌/认识/知道/看过/玩过/用过` 等动词，会保持关系方向，但支持从宾语反查主语，例如记住 `d喜欢猫` 后可以问 `谁喜欢猫`。亲属和角色关系不会粗暴对调，例如 `hzh是小明的儿子` 可回答 `小明的儿子是谁`，但不会把“儿子”和“小明”错误地视为同义词。

这类命中明确群记忆的问题会走确定性关系解析，不再完全依赖大模型猜测；回答会保留原事实，同时使用几种自然模板补一点口语化修饰，避免只回复一个孤零零的名字，也不会为了丰富语气新增未记录的关系或经历。

### 删除指定记忆

使用 `@机器人 删除记忆 关键词`，或更短的 `@机器人 删除关键词`。程序进行区分大小写的文字包含匹配，删除所有包含该段完全相同文字的共享记忆。例如 `删除 hzh` 会删除内容中带有 `hzh` 的身份、经历和性格记录，但不会删除无关成员的记录。匹配删除后，当天临时夺舍上下文也会清空，避免旧信息残留。


## 夺舍历史检索配置

可在 `.env` 中调整：

```dotenv
POSSESSION_RECALL_HISTORY_COUNT=500
POSSESSION_RECALL_RESULT_LIMIT=12
```

`POSSESSION_RECALL_HISTORY_COUNT` 控制从 NapCat/本地样本池最多保留和扫描多少条目标成员公开文本；`POSSESSION_RECALL_RESULT_LIMIT` 控制每次问题最多向模型提供多少条匹配片段。数值越大覆盖更广，但上下文和响应成本也会增加。
