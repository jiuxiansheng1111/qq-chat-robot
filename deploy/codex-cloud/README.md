## 当前范围

- 代码包包含当前工作目录中的聊天机器人、角色提示、菜单、资源，以及已安装的七个外部插件源码。
- 本机 `.env`、账号密钥、QQ 登录状态、聊天数据库、训练素材、语音模型与 Python 环境均未放入代码包。
- 本机原始训练素材保留。云端试运行使用独立实例，不能与本机实例同时连接同一个 QQ/NapCat 事件源。
- 普通聊天使用 AstrBot 原生插件流程；点歌、翻唱等业务入口保留。语音和翻唱需要另行迁入模型及运行时后验收。

## 在 Codex 中准备环境

1. 新任务选择 **Work in → Cloud → Select environment → Create environment**，选择现有代码仓库。当前本机的未提交修改没有推送到远端，应将本次代码准备包导入私有云端工作目录后再测试。
2. 先运行 `python scripts/start_codex_cloud.py` 查看预检。该命令只报告环境，不启动服务，也不改动本机数据。
3. 使用 Python 3.12；安装项目与本机已验证的 AstrBot 版本：

   ```bash
   python -m pip install -e . 'astrbot==4.28.2'
   ```

4. 逐个安装 `cloud_plugins/*/requirements.txt` 声明的依赖，保留各插件的版本和接口。本包里的构建产物可直接使用，不需要重新发布插件。
5. 在 Codex 私有环境变量中设置独立的 `ASTRBOT_DASHBOARD_INITIAL_PASSWORD`。模型密钥通过私有环境变量或 AstrBot 配置提供，不提交到仓库。
6. 运行 `python scripts/start_codex_cloud.py --start`。入口只用于 Linux 云端，在 `data/codex-cloud-instance/` 创建独立实例，输出进程号、日志位置与面板就绪状态。它不会购买资源、创建云端环境、接入 QQ，或绕过平台的 VM 生命周期。
7. 面板端口为 6185。确认 Codex 环境实际支持的面板访问方式；如果没有端口预览或连接能力，记录这一阻碍，不能以终端中的“启动成功”代替验收。
8. 在云端面板配置现有智谱模型；将“普通消息使用现有角色聊天”保持关闭，使新增插件参与聊天。
9. 云端自主学习使用 SQLite，三个文本模型选择已配置的主模型；陪伴插件的名字使用“小丛雨”。现有安装包中的完整命令可通过帮助菜单查看。

## QQ 接入是独立的必要步骤

当前账号登录在 Windows 上的 NapCatQQ Desktop，不能靠复制聊天机器人代码迁走。

必须在云端实际安装并运行兼容的 QQ/NapCat 实例、完成账号登录、保留它的持久数据，再将反向 WebSocket 指向云端 AstrBot 的 6199。用户应在云端的正常登录界面完成扫码或验证；不能把本机 QQ 凭证提交到公共仓库。云端只启动 AstrBot 而没有迁移 NapCat 时，电脑关机后仍无法接收 QQ 消息。

## 验收标准

1. 云端面板、AstrBot 插件和 OneBot 连接分别就绪，新增插件无加载失败。
2. 用户自选测试会话能够正常对话、使用菜单、模拟人生和表情，不向其他群发送测试消息。
3. 用户关机后，QQ 消息仍能到达云端并收到回复。
4. Codex 当前任务结束、闲置、再次打开后，分别检查后台进程、账号连接和数据是否仍存在。**文件能恢复不等于后台进程一直运行。**
5. 重启测试后，账号状态和数据库可以恢复，并验证没有双重回复。
6. 语音与翻唱另行检查模型、磁盘、内存与推理速度；没有通过前保持关闭。

只有上述连接与生命周期测试通过，才能报告“已在 Codex 云端托管”。不使用循环发消息或空跑任务来规避平台生命周期。

## 官方能力边界

[OpenAI 官方 Cloud environments 文档](https://learn.chatgpt.com/docs/environments/cloud-environments)说明，云端任务可在电脑休眠时继续工作，已有任务可恢复自己的文件；默认 VM 为 2 核 / 8 GiB / 8 GiB 磁盘或 4 核 / 16 GiB / 32 GiB 磁盘，取决于套餐。文档说明的是任务与可恢复状态，没有给出此 QQ 机器人持续托管的可用性承诺。

此结论不是已经验证失败，也不是已经验证能常驻；实际云端运行结果必须单独记录。
